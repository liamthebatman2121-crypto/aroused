# Security fix plan

Scope: fix security defects already recorded in `PRODUCTION_ARCHITECTURE.md` and `PRODUCTION_READINESS.md`, plus directly related authorization/publication paths found during route review. No UI changes, database migration, fake provider, or fabricated safety result. Required scanner, processing, known-content, safety, moderation, and age-assurance states remain mandatory and fail closed.

| Issue | Exact file and route/function | Current behavior | Vulnerability | Secure behavior | Test required |
|---|---|---|---|---|---|
| Authentication: account enumeration | `server.mjs`; `POST /auth/signup`, `/auth/resend-code`, `/auth/verify-email` | Existing accounts, absent pending codes, expired/incorrect OTPs, and exhausted attempts have distinguishable responses. | An attacker can discover registered accounts and their verification state. | Return generic externally visible responses for identity-sensitive outcomes, preserve private rate limits, and do not issue a session or create an account unless a valid code is verified. | Existing and new email response parity; missing/expired/incorrect OTP parity; wrong code never logs in; resend rate limit remains effective. |
| Authentication: missing password recovery | `server.mjs`; `password_reset_tokens` table has no request/consume API | No password reset route or email flow exists. | Users cannot safely recover accounts; ad hoc support workarounds may bypass identity checks. | Implement generic rate-limited request and consume APIs, random one-time token stored only as a hash, short expiry, real Resend delivery only, password replacement, and revocation of all existing sessions. With Resend absent, do not create a usable token or claim delivery. | Unknown/known request response parity; provider-unconfigured fail-safe; valid token changes password and invalidates all sessions; expired/used/invalid tokens denied; reset rate limit. |
| Session: malformed cookie and logout revocation | `server.mjs`; `sessionUser()`, `createSession()`, logout route | Cookie decode can throw on malformed percent encoding; verify logout route invalidates server record and login rotation behavior. | Malformed cookie can produce server errors; cookie-only logout could leave a replayable bearer session. | Decode defensively; logout deletes the matching hashed session and expires cookie; session rotation invalidates prior token; expired/revoked tokens are denied. | Malformed cookie returns anonymous/401 without 500; logout old cookie denied; rotated old token denied; expired token denied. |
| Session: cookie transport/config | `server.mjs`; `createSession()`, `clearSessionCookie()` | `Secure` is set only in production; persistent session is 30 days. | Production cookie safety depends on environment being correctly set; no regression test for cookie flags. | Preserve Secure/HttpOnly/SameSite/Path/Max-Age on issuance and deletion; tests verify production cookie flags and invalidation. | Production-mode login cookie flags; logout cookie expiry. |
| CSRF / origin protection | `server.mjs`; `postAllowed()`, unsafe API dispatcher | Cross-site Fetch Metadata and disallowed Origin rejected; missing Origin with cookie is rejected unless same-origin metadata; no synchronizer token. | Inconsistent/missing browser metadata or origin handling can enable cookie-authenticated state changes. | Keep exact allowlist; reject an unsafe cookie-authenticated request unless it has an allowed Origin or explicit `same-origin` Fetch Metadata; reject cross-site and malformed/untrusted Origin. No UI token change. | Allowed same-origin and direct API requests with explicit same-origin metadata pass; cross-site, hostile Origin, and cookie request without origin/metadata fail. |
| Authorization: moderator/admin separation | `server.mjs`; `requireModerator()`, `/admin/*`, `/moderation/*` | Role helpers protect current routes, but the regression suite does not exercise the full role/privilege matrix. | Route additions or wrong minimum role can expose reports or permit decisions/settings without sufficient privilege. | Centralize role hierarchy checks and enforce explicit admin-only settings/account enforcement, moderator read, senior-moderator decisions; authorization always read from current DB role. | User denied moderator/admin; moderator reads cases but cannot decide/admin; senior moderator can decide but cannot admin; admin can admin. |
| Authorization: server bootstrap role promotion | `server.mjs`; first-run admin bootstrap block | Environment values can promote the configured account to admin on every startup. | Repeated deployment/restart can silently restore revoked privilege. | Only create/promote on explicit first-run bootstrap when no admin exists; never un-suspend/re-promote an existing identity on later starts. | Existing demoted/suspended bootstrap identity stays unchanged after restart; fresh first admin bootstrap still works. |
| Upload access: unknown/unassociated files | `server.mjs`; `GET /uploads/:name` | If a filename is not associated with `album_media`, the file is served without auth. | Orphaned, partially deleted, or future-stored private files can be disclosed by guessed/learned names. | Allow only verified avatar records or an associated media row that passes the same media authorization and all publication gates. Deny all other paths. | Public avatar allowed; unknown/orphan upload denied; media association owner/private/unpublished/quarantined/rejected/public matrix. |
| Upload access: traversal/malformed path | `server.mjs`; static `/uploads/:name`, `/media/:id` | Decode can throw outside handler; basename is relied on to constrain filenames. | Malformed encoding may cause 500; path parsing can drift into an unsafe path. | Decode in a guarded helper; reject separators/NUL/dot traversal; resolve only a server-recorded storage key and use consistent no-sniff/private cache headers. | Encoded traversal and malformed `%` denied without 500; valid stored keys work only when authorized. |
| Media access: pipeline and account status | `server.mjs`; `/media/:id`, `/uploads/:name`, `mediaPipelineReady()` | Read paths allow owner access to media regardless of missing/blocked pipeline; public path checks state with inconsistent predicates. | Owner path can access quarantined/rejected bytes; public routes can drift from required status checks. | Central `mediaPublicationReady()` requires complete explicit `READY/CLEAN/READY/CLEAR/CLEAR/APPROVED`; owner preview only for non-rejected, non-quarantined media (if retained); rejected/quarantined blocked for everyone except explicitly privileged controlled moderation path (none implemented). | Owner and another-user requests for pending/private/unpublished/quarantined/rejected media denied; public only for complete gate. |
| Media access: direct story/media URL IDOR | `server.mjs`; `lookupStory()`, `GET /stories/:id`, `/media/:id`, album metadata route | Direct stories may be returned when parent album is not published; public/unlisted album route and bytes use different checks. | Guessing a numeric ID/slug or requesting raw media URL may bypass album-level status/visibility. | One access predicate checks story published, parent album published, visibility and authorized unlisted slug, owner, and every media pipeline record. Apply to metadata, feed, story, and bytes. | Direct story and byte URLs for draft/processing/private/unlisted-without-link denied; valid public and authorized unlisted allowed. |
| Publication: direct API and add-media paths | `server.mjs`; `POST /albums`, `/albums/:id/publish`, `POST /albums/:id/media` | Publish checks album media `state='ready'`, not the full pipeline; creation/addition can set an album/story state inconsistently. | A malicious client can call APIs directly and publish without provider decisions. | A single `canPublishAlbum()` checks owner eligibility, current policy/declarations, at least one file, every file's `state` and pipeline states, review approval, valid visibility, and allowed schedule; only this helper transitions to `published`. No provider means denied. | Direct immediate publish and publish-at-create denied with NOT_CONFIGURED; exact fully gated fixture allows; missing single provider state denies. |
| Publication: visibility edit bypass | `server.mjs`; `PATCH /albums/:id` | Already-published album can change `visibility` or other publication fields without a transactional full gate; DB writes occur outside transaction. | Draft/private/quarantined media may be made public through visibility changes, or published status may be retained while schedule/review state changes. | Publication-affecting edits lock/check inside transaction; public status can be retained or entered only if `canPublishAlbum()` passes. Any change to media or public status that invalidates gate reverts to private draft/processing. | PATCH visibility to public fails when any gate missing; private/unlisted transitions behave as policy allows; atomic rollback on denial. |
| Publication: schedule bypass | `server.mjs`; `publishDueAlbums()` and schedule routes | Scheduler checks pipeline rows but not owner enforcement, current eligibility, declarations, current visibility/status, and full canonical gate; updates rows without row-count/coupled story checks. | Scheduled post could publish after eligibility revoked or through inconsistent album/story state. | Scheduler re-evaluates canonical gate in a transaction at due time and publishes album/story atomically only when all current conditions pass; otherwise remains private draft. | Due schedule with safe fixture publishes; missing provider/declaration/eligibility/review keeps private; direct scheduler test. |
| Publication: legacy/story endpoint and non-album story paths | `server.mjs`; `POST /stories/upload`, `DELETE /stories/:id`, story/feed reads | Legacy upload disabled (410); legacy stories/media paths may have different publication semantics. | A legacy or orphan story/media row may lack an associated album pipeline gate and be publicly returned. | All public story/media reads require an associated album and full publication gate, or an explicit safe legacy record meeting equivalent server-side criteria; deny unassociated raw media. Remove/delete keeps media inaccessible. | Legacy unassociated story cannot publish/read media; removed/deleted content denied on all routes. |
| Other media exposure: avatar/static file selection | `server.mjs`; `/uploads/:name`, static file fallback | Avatar URLs use `/uploads`; fallback served basename-selected files. | Filesystem presence alone could disclose arbitrary files; avatar bytes had no publication-safety record. | Only the owning account can fetch its avatar until an actual server-side approved-publication path exists; static routes map to known HTML assets only; unknown files return 404. | Owner avatar allowed; another user's avatar denied; arbitrary file/orphan denied; unknown static path 404. |
| Rate limiting and brute-force protections | `server.mjs`; `rateLimit()`, auth/upload routes | Some auth routes limited; no upload-specific limit and rate buckets are not bounded/pruned. | Abuse can consume upload/memory/storage or grow DB buckets; proxy identity can be shared. | Add per-account upload request limit before reading bodies, prune expired buckets on bounded cadence, and retain existing auth limits. Never trust forwarded IP without explicit proxy config. | Rate-limit test verifies allowed quota then 429 for signup/login and upload. |

## Verification matrix

Tests must cover both expected allow and expected deny for each applicable route and role. Use an isolated temporary database/upload directory and direct HTTP requests with cookies/Origin/Fetch Metadata headers. Create explicitly gated media fixtures only by test SQL; production code must never synthesize provider success.
